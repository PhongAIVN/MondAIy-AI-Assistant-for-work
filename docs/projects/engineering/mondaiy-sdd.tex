\section{Kiến trúc tổng thể}
mondaiy dùng kiến trúc modular monolith: FastAPI là API edge; service và connector tách ranh giới nghiệp vụ; worker xử lý run dài; PostgreSQL là authoritative store; Redis phục vụ queue/rate limit; MinIO lưu object khi cần; React web, Expo mobile, extension và Telegram là client channel. Lựa chọn này giảm chi phí đồng bộ schema, auth và audit ở giai đoạn sản phẩm thay đổi nhanh, nhưng vẫn cho phép tách worker/API khi tải tăng.

\section{Luồng chi tiết}
\subsection{Đồng bộ nguồn tới evidence}
\begin{enumerate}
\item API hoặc worker xác thực user, connection và source scope.
\item Connector lấy dữ liệu trong giới hạn thời gian/trang/kích thước; token lỗi trả về lỗi xác thực có nguyên nhân.
\item Pipeline normalize dữ liệu, lọc item, trích xuất task/metadata và persist theo transaction/idempotency boundary.
\item Run ghi counts \code{filtered}, \code{rejected}, \code{extracted}, \code{resolved}, \code{persisted} và trạng thái \code{completed}/\code{blocked}/\code{failed}.
\end{enumerate}

\subsection{Chat grounded và action draft}
Client gửi conversation turn $\rightarrow$ API xác thực/kiểm tra consent $\rightarrow$ retrieval chỉ trả evidence thuộc user $\rightarrow$ agent gọi tool được cấp capability $\rightarrow$ response có citation hoặc abstain. Nếu ý định là write, tool tạo proposal/draft; service chỉ ghi task/event sau confirm. Retry phải không ghi đè phần draft do user đã sửa.

\subsection{Nhập task từ DOCX/XLSX}
Mobile share intent hoặc document picker tạo multipart \code{files}; endpoint \code{/api/v1/excel/task-proposals} kiểm tra tối đa 5 file, suffix DOCX/XLSX và trần 200 KB, đóng file sau xử lý, trích proposal rồi trả để người dùng thêm từng task. Share extension, widget extension và app chính chia sẻ App Group trên iOS nhưng có bundle identifier riêng.

\section{API và error contract}
API versioned dưới \code{/api/v1}. Request mang bearer token trừ auth bootstrap; error dùng HTTP status + \code{detail} có thông điệp hành động được. Các endpoint representative: auth/session, connections/OAuth, tasks, calendar, conversations, meeting notes, routines, notifications và \code{excel/task-proposals}. Pipeline response nên chuẩn hóa:\\
\begin{center}\code{\{status, filtered\_count, rejected\_count, extracted\_count, persisted\_count, error\}}\end{center}
Không được mô tả pipeline là thành công nếu connection thiếu refresh token, không tìm thấy connection hoặc fetch bị chặn.

\subsection{Chuẩn giao tiếp bắt buộc}
\begin{tabularx}{\textwidth}{>{\bfseries}p{3.1cm}X}
\toprule Thành phần & Contract \\ \midrule
Auth & Client gửi \code{Authorization: Bearer <user-session-token>}; service-to-service chỉ dùng internal token ở server. Mọi object read/write kiểm ownership và consent còn hiệu lực. \\
Correlation/idempotency & Response echo \code{X-Request-ID}. Write quan trọng nhận \code{Idempotency-Key}; key trùng nhưng payload khác trả \code{409 IDEMPOTENCY\_KEY\_CONFLICT}. \\

Error envelope & \code{\{error: \{code, message, details, request\_id\}\}}; không đưa token, raw source hoặc stack trace cho client. \\
State machine & Source: \code{not\_connected|connected|syncing|paused|error|revoked}. Action draft: \code{drafted|previewed|confirmed|handoff\_opened|completed|cancelled}. Transition trái phép trả \code{409 STATE\_CONFLICT}. \\
\bottomrule
\end{tabularx}

\section{Hạ tầng và bảo mật}
Production VM dùng Docker Compose. Fast path chỉ build/recreate \code{p004-backend} và \code{worker}; không restart database, Redis, MinIO hay shared proxy. Production \code{.env} trên VM là authoritative và không được sync từ workstation. Health endpoint xác nhận API sau deploy; image trước đó được tag rollback. Vercel quản lý frontend web; EAS/TestFlight là pipeline iOS riêng.

Các boundary an toàn: OAuth scopes tối thiểu, allow-list file/mime/size, chống zip-bomb và timeout extractor; guardrail coi cả attachment lẫn nội dung nguồn là untrusted; secret không commit/log; datetimes timezone-aware; AI consent trước khi gửi question/image/source context cho provider.

\subsection{Threat model và release control}
\begin{longtable}{p{3.4cm}p{4.3cm}p{5.6cm}}
\toprule Threat/failure & Control thiết kế & Evidence trước release \\ \midrule\endhead
Cross-user access hoặc privilege escalation & Ownership check ở API/service/query, RLS theo source of truth, cache permission-scoped & Denial test giữa hai user, RLS/API test và review query mới. \\

Destructive deploy/data migration & Exact SHA artifact, health check, rollback image and tested backup/restore procedure & Deploy record gồm SHA, migration, health, rollback target và restore-test date. \\

\end{longtable}

\subsection{Operational SLO và disaster readiness}
Mục tiêu release lấy từ SRS: 95th percentile batch/briefing $\leq2$s, first answer $\leq10$s, action draft $\leq3$s tại tải 50 active users. Monitoring phải tách latency, error class, queue retry/age, blocked run và provider availability. Không có RPO/RTO hoặc retention duration được phê duyệt trong nguồn hiện tại; chúng là \textbf{release blocker cho production-scale claim}, không được điền bằng số giả. Trước pilot phải có owner, lịch backup, restore drill và rollback runbook có kết quả.

\section{Quyết định và rủi ro mở}
Các drift lịch sử (Telegram, custom JWT, runtime LLM provider) phải được đối chiếu với PRD/ADR trước khi mở rộng. Tăng tải phải dựa trên metric queue/latency/error thực tế trước khi tách thêm service.
