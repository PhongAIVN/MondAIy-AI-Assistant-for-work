# Native Mondaiy mobile design

- **Objective:** Replace the React Native app's WebView shell with an official, mobile-native Mondaiy experience.
- **Research:** `docs/projects/product/prd.md`, `docs/projects/design/wireframe-ui-flow.md`, deployed `https://www.c3-app-004.io.vn`, `client/web-app/src/index.css`, and the existing Expo app under `apps/mobile`.
- **Scope:** `apps/mobile/App.tsx` now starts the native product shell. `MobileProduct.tsx` provides onboarding, sign-in/sign-up, Home/Daily Brief, discovery, content detail, search, assistant, notifications, profile and settings, with a one-thumb bottom navigation. It carries the established paper/teal/sage palette, serif display hierarchy, 44px+ controls, safe areas, empty state, loading submit state and success feedback.
- **Scope update — Google and email authentication:** The native app now sends email sign-in/sign-up to the production auth endpoints, opens the backend-owned Google OAuth session in the system browser, verifies the exact `mondaiy://auth/google` callback, exchanges the single-use code for tokens, then stores them only in Expo SecureStore. The backend allowlist accepts that one configured mobile URI and still rejects any other deep-link target.

- **Files:** `apps/mobile/App.tsx`, `apps/mobile/src/components/MobileProduct.tsx`, `apps/mobile/src/api/client.ts`, `apps/mobile/src/mobileDesign.ts`, `apps/mobile/tests/mobile-design.test.ts`, `apps/mobile/README.md`, `apps/mobile/src/config.ts`, `apps/mobile/tests/config.test.ts`, `apps/mobile/package.json`, `apps/mobile/package-lock.json`, `src/api/auth.py`, `src/config.py`, `.env.example`, `.env.prod.example`, `tests/test_api/v1/test_google_login.py`. The primary navigation is Home, Sources, Chat, Notifications and Profile. Added exact mobile callback acceptance for provider connection intents.
- **Scope update — Apple sign-in:** Added the iOS-native Sign in with Apple control and `POST /api/v1/auth/apple/session`. The server verifies the signed Apple identity JWT against Apple's public JWKS, issuer and configured iOS bundle audience before issuing P-004 JWTs. `users.apple_subject` preserves the stable Apple identity so a later Apple login works even when Apple no longer returns its relay email. The startup migration adds the nullable unique field safely to existing pilot databases. Production `APPLE_CLIENT_ID` and the iOS bundle identifier use `com.mondaiy.product`; no OAuth secret is stored because native identity-token verification does not require one. Apple Developer must still enable Sign in with Apple for that exact App ID before a real iOS build can authenticate.

- **Scope update — native workspace polish (2026-08-16):** Redesigned the real Sources tab into provider cards with account/status badges, a privacy summary and an explicit disconnect confirmation. Disconnect now updates optimistically, disables repeat presses, refreshes server state and confirms the result. This matches the backend's existing behaviour: a Google revoke may be rejected by Google after the P-004 connection has already been removed locally; the application treats the successful local removal as the completed action. Home now switches between the real task list and a seven-day calendar that calls `GET /api/v1/calendar/events` with the authenticated user's token. Chat renders backend HTML as rich text (paragraphs, emphasis, lists and links) instead of displaying markup literally. Added the Cormorant Garamond / Nunito Sans mobile font pair and loading gate.

The API client test verifies the authenticated calendar range request. No VM configuration or backend deployment was needed because this change consumes existing production endpoints; an updated Android/iOS build is required to deliver it to installed devices.
